# HiiCampus Habit Tracker

A Firestore-backed daily habit tracker built with Flutter, BLoC and Clean
Architecture.

The app has three screens:

1. **Today's Habits** – today's progress, points and the habit list.
2. **Add Habit** – validated form that persists a new habit.
3. **Habit Detail** – the last seven days plus the current streak.

## Architecture

```
Presentation → Cubit → UseCase → Domain Repository Interface
             → Data Repository Implementation → Firestore Data Source
```

- Cubits depend on UseCases only; UseCases return `Either<Failure, T>` (dartz).
- Domain entities are plain Dart (freezed) and know nothing about Firestore.
- Firestore documents, serialization and entity/model mapping live in the data
  layer (`lib/features/habits/data`).
- The only place that translates data-layer exceptions into domain `Failure`s
  is `HabitRepositoryImpl`.

```
lib/
  core/                 # config, errors, DI, router, theme, date utilities
  features/habits/
    data/               # firestore data source, models, repository impl
    domain/             # entities, repository interface, use cases
    presentation/       # cubits, pages, widgets
  firebase_options.dart # generated by FlutterFire CLI
tool/                   # development seed script (not shipped in the app)
```

## Requirements

- Flutter 3.44.x / Dart 3.12.x (no FVM required).
- Firebase CLI (`firebase`) and FlutterFire CLI (`flutterfire`) for
  configuration/deployment.
- A Firebase project with Firestore enabled (see below).
- For the Firestore **emulator**: a JDK **21+**. The bundled emulator refuses to
  run on older JDKs.

## Firebase project and configuration

- **Project id:** `hiicampus-habit-tracker` (also recorded in `.firebaserc`).
- Android is configured end to end:
  - `android/app/google-services.json`
  - the `com.google.gms.google-services` Gradle plugin
- iOS is **not** configured yet: `ios/Runner/GoogleService-Info.plist` is
  missing. Run `flutterfire configure` (which writes that file) before
  building for iOS.
- `lib/firebase_options.dart` is generated and is imported by
  `lib/main.dart`, which initializes Firebase exactly once at startup.

Configuration files are already committed for this project. To regenerate them
for a different project, use `flutterfire configure`.

## Firestore schema

All dates are **local calendar days**, formatted `yyyy-MM-dd`. This is the
single, documented date-boundary convention: the app writes and reads keys in
the device's local timezone, so a "day" always matches what the user sees.

```
users/{userId}/habits/{habitId}
  name:        string
  description: string
  points:      number
  createdAt:   timestamp

users/{userId}/habits/{habitId}/completions/{yyyy-MM-dd}
  completed:   boolean
```

- The completion document id **is** the day, so the date is not duplicated in
  the body. Only completed days are stored; clearing a completion deletes the
  document.
- Document ids for habits are stable, so writes/re-seeds are idempotent.

### Identity

Firebase Authentication is **not** configured, so the app cannot derive a real
user id. `lib/core/config/dev_identity.dart` provides the single documented
development identity:

- default user id: `dev-user`
- override at run time: `flutter run --dart-define=HABIT_USER_ID=dev-alice`

This is **not authentication** and provides **no** user isolation.

## Security rules and identity assumptions

`firestore.rules` is deployed and currently:

- allows unauthenticated `read`/`write` **only** under `users/dev-user/**`, and
- denies everything else.

This is a **testing-only** posture for a development project: anyone with the
(public) API key can read/write the `dev-user` namespace. It must be replaced
before any real release. The recommended production rule set, once Firebase
Authentication is enabled, is:

```
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

Deploy rule changes with:

```sh
firebase deploy --only firestore:rules --project hiicampus-habit-tracker
```

## Running the app

```sh
flutter pub get
flutter run                 # Android
```

`main()` initializes Firebase with `DefaultFirebaseOptions.currentPlatform` and
then builds the dependency graph. Once signed in is implemented, only the
`UserIdProvider` registration needs to change.

## Development seed data (development only)

`tool/seed_dev_data.dart` creates five sample habits plus a short completion
history for the `dev-user` namespace. It is:

- **idempotent** – existing documents are skipped, never overwritten;
- **non-destructive** – it never deletes or resets anything;
- **verifying** – it reads every planned document back and reports mismatches.

Planned documents: `users/dev-user/habits/{habitId}` and
`users/dev-user/habits/{habitId}/completions/{yyyy-MM-dd}`.

```sh
# Preview without writing
dart run tool/seed_dev_data.dart --dry-run

# Seed the Firestore emulator (needs JDK 21+)
FIRESTORE_EMULATOR_HOST=localhost:8080 dart run tool/seed_dev_data.dart --emulator

# Seed a live development project (requires explicit opt-in)
dart run tool/seed_dev_data.dart --allow-live
```

Live mode uses your existing `firebase login` session (or the
`FIREBASE_ACCESS_TOKEN` environment variable) and refuses to write without
`--allow-live`. Never point it at a production project.

## Tests and quality checks

Unit and widget tests do **not** need any Firebase credentials.

```sh
dart format lib test tool
flutter analyze
flutter test
```

Integration/read-back verification of seeding can be done with the emulator:

```sh
firebase emulators:exec --only firestore --project hiicampus-habit-tracker \
  "dart run tool/seed_dev_data.dart --emulator"
```

If the emulator cannot start (it requires JDK 21+), the seed script can instead
be pointed at a confirmed development project with `--allow-live`.

## Manual steps that remain

- Configure iOS (`flutterfire configure` to generate
  `ios/Runner/GoogleService-Info.plist`).
- Replace the development seed history with real user data.
